Building a Forge


Goal
Goal: Understand what a Forge is, where it lives, and what your game must provide.
Tip: A Forge is game-specific. Each game defines its own drawing & output rules and export behavior.

What is a Forge?

A Forge is the game-provided component that tells Card Forge Studio how to build and export cards for your game.

It's also where you
  • Bring in your game's custom classes
  • Register your cell processor lookup function
  • Define your own globals
  • Hook and modify the user environment used in the Lua editor
Note:
Each time a project is loaded, the Lua package path is reset to include your game's Scripts directory.

A Forge typically handles

  • Card image sizing and layout rules
  • Drawing and composition (frames, text, layers, etc.)
  • Image and text rendering decisions
  • Card export behavior (what gets generated and where)
  • Any game-specific rules needed for card output

Where does the Forge live?

Each game must include its Forge in the game’s Scripts directory.

Required file: Your game must provide a file named Init.lua in the Scripts directory.
By default, an Init.lua file is created for you when you build a new project but you'll need to modify it to suit your game.

Init.lua requirements

The file must:

  • Be named exactly: Init.lua
  • Be located in the game’s Scripts directory
  • Return a Forge object when loaded

What “return a Forge” means

Card Forge Studio loads a project's Init.lua when that project is loaded and expects it to return a Forge object. That returned Forge is what the editor uses for card rendering and exporting.

We need to register a cell processor resolver. In plain English, that means we need to tell the class responsible for processing each cell in our CSV data, how to find the cell processor class for each card class in our game.

In the example below, we're using a class structure that uses Card->Family->Type (like Creature->Dragon). The proc resolver finds and returns the processor class associated with each class (which is often each class itself or a parent).

While most classes will be their own cell processors, some games may be designed such that a parent class can be the processor for the child classes. This is shown in the example as well where the Orc class uses the cell processor from the Creature class.

This design can be useful if a lineage of cards needs only one cell processor. That decision is, of course, up to you.


Note:
We'll get more into class design later. 
--============================================================
--  Init.lua (example)
--  Fantasy example: Card -> Creature -> Dragon
--                  Card -> Spell    -> Damage
--============================================================

local _tProcsByLineage = {};

local function RegProc(sLineage, cProc)
    _tProcsByLineage[sLineage] = cProc;
end


--🅻🅾🅰🅳 🅲🅰🆁🅳 🅲🅻🅰🆂🆂🅴🆂 🅰🅽🅳 🆁🅴🅶🅸🆂🆃🅴🆁 🅿🆁🅾🅲🆂
Card        = require("Card");
Creature    = require("Card.Creature");
Spell       = require("Card.Spell");

Dragon      = require("Card.Creature.Dragon");     RegProc("Card.Creature.Dragon",    Dragon);
Goblin      = require("Card.Creature.Goblin");     RegProc("Card.Creature.Goblin",    Goblin);
Orc         = require("Card.Creature.Orc");        RegProc("Card.Creature.Orc",    Creature);

Damage      = require("Card.Spell.Damage");        RegProc("Card.Spell.Damage",       Damage);
Healing     = require("Card.Spell.Healing");       RegProc("Card.Spell.Healing",      Healing);


--🆁🅴🆂🅾🅻🆅🅴 🅿🆁🅾🅲 🅿🅴🆁 🆁🅾🆆
--[[The Proc Resolver callback gives us the Card Set name
	and the CSV row table for the selected row (the one that
	is requesting the proc class)]]
ProcSys.RegisterProcResolver(
    function(sSet, tRow)
        local sIndex =  tRow.Family ..'.'..
                        tRow.Class

        return _tProcsByLineage[sIndex];
    end
);


--🅲🆁🅴🅰🆃🅴 🅰🅽🅳 🆁🅴🅶🅸🆂🆃🅴🆁 🅴🆇🅿🅾🆁🆃 🅵🆄🅽🅲🆃🅸🅾🅽🆂
-- Example source CSV: Cards.csv
-- Exports rendered images into:
--   <_pCardExport>\\\\.png
ProcSys.RegisterExporter(_pCSVSource.."\\Cards.csv",
    function(D, hImage, cProc, tRow)
        local pExport = _pCardExport.."\\"..tRow.Family.."\\"..tRow.Class;

        if not (Folder.DoesExist(pExport)) then
            Folder.Create(pExport);
        end

        DrawingImage.Save(hImage, pExport.."\\"..tRow.Name..".png", DRAW_FORMAT_PNG);
    end
);


--override the basic GetUserEnv function
local _GetUserEnv = GetUserEnv;

function GetUserEnv()
    local tRet = _GetUserEnv();

	--[[we can add functions, strings, and whatever
		else we want to the user environment used
		in the Lua editor]]
	if not (tRet.GetMaxHealth)
		tRet.GetMaxHealth = function()
			return tRow.Health + tRow.BonusHealth;
		end
	end

	--return the modified environment
	return tRet;
end

--🅴🆇🿿🅾🆁🆃 🆃🅷🅴 🅵🅾🆁🅶🅴
return Forge(1125, 825, 825, 1125);
